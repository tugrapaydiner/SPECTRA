# SPECTRA: compiled-query review and implemented checkpoint

**13 October 2026. Branch `research/compiled-query-validation`. Development only.**

The important advance in this checkpoint is a credible working generic
knowledge-compilation comparator and an auditable complete-cost experiment,
not a new speedup to SPECTRA's native solver. The public solver, its defaults,
and the frozen WAP evidence are unchanged. The prior whole-program assessment
was **67/100**; these internal results do not automatically justify a new grade,
a high-90s claim, or a universal reasoning result.

## Findings and changes

### 1. The first CUDD comparator was not a sufficient challenge

The inherited balanced-construction experiment timed out on all CUDD cells of
both WAP graphs. That cannot establish a numerical performance ratio against
CUDD. Its receipts remain in run **38466688942** and in the recovery evidence.
The failure motivated a stronger baseline rather than a declaration of victory.

Frontier clause scheduling and independent redundant binary equivalence seeds
were added as separately named variants. The original configurations remain
available. None consumes SPECTRA's index or previously solved answers.

Profiling also exposed a concrete measurement distortion: in the pinned
`dd/cudd.pyx`, `len(bdd)` calls `Cudd_CheckZeroRef`, a manager-wide reference audit.
Repeated soft-node guard scans were being charged as if they were inherent BDD
query work. New constructions amortize that diagnostic over 64 operation
checkpoints, with forced scans before and after construction. The old arm keeps
its old interval. This is a **soft** diagnostic, not a hard node or RSS bound.
The per-answer original-input correctness checker was never sampled or removed.

### 2. Generic reduction makes CUDD a substantially stronger comparator

`reduced.py` now independently computes signed equivalences from the original
binary CNF, substitutes them into every clause, performs event-driven unit
propagation, and compiles the residual with native CUDD. Every original variable
has a total reconstruction map, including fixed and unconstrained variables.
Current requests are translated without mutating the root. Full original-colour
answers are reconstructed and checked against original edges, lists and requests.

| Development input | Original Boolean variables | Residual variables | Original normalized clauses | Residual clauses |
|---|---:|---:|---:|---:|
| WAP05 | 905 | 72 | 2,054 | 30 |
| WAP06 | 947 | 71 | 2,160 | 32 |

These reductions are computed by the generic comparator itself. Its construction,
map, conditioning and full reconstruction are all charged. They also sharpen the
novelty question: much of the available structure is recoverable by established
logical preprocessing. The contribution must survive comparison on complete
service cost, not rely on withholding that structure from competitors.

The [reduction contract](REDUCTION_CONTRACT.md) gives the model-preservation and
current-request argument. It is a mathematical derivation with exhaustive and
randomized checks, not a machine-checked implementation proof or a new algorithmic
first. The CUDD engine is independently maintained; our reducer is project code.

### 3. The complete-cost harness keeps missing work visible

The new study freezes source, backend code, original inputs, exact query prefixes,
native build identity, environment and randomized paired schedule before trials.
It retains original output bytes, hashes, stage timing, cold wall cost, process
status and failed trials before analysis. A timeout or UNKNOWN never becomes an
UNSAT decision or an infinite-speedup denominator. Interrupted work is recoverable
without silently retrying failed cells.

The warm complete session includes input decoding/validation/hashing, solver and
independent-checker construction, every query and full witness check, SCQ1 output
materialization, hashing, diagnostics and disposal. Process launch/import cost is
separately retained, not hidden inside a claim about cold starts. Native library
build and post-run audit are outside this endpoint and explicitly disclosed.

Post-run SAT replay checks original graph constraints directly in Python. A
separate original-domain implication checker challenges UNSAT without consuming
the generic CNF encoder, reduction map or BDD. This does not manufacture a portable
UNSAT certificate. Linux wall deadlines and address-space limits are enforced
outside the solver. `RLIMIT_AS` is not a hard RSS cap.

## Final matched development result

The final matrix uses two already exposed graphs, prefixes of 1 and 1,024 requests,
three paired repetitions, eight explicit arms and a 15-second worker deadline.
Each of the local Python 3.13, GitHub Python 3.11 and GitHub Python 3.13 matrices
has **96 scheduled sessions: 90 COMPLETE and 6 TIMEOUT**. Every reduced-CUDD arm
completes every scheduled cell. The six remaining failures belong to unreduced
frontier-BFS at 1,024 requests, so that comparison has **no finite ratio**.
Each matrix's original-input audit checks **43,056 SAT outputs**.

The following are geometric means of within-graph mean complete-session ratios,
**SPECTRA SCC time / comparator time**, for 1,024 requests. Smaller is better for
SPECTRA. They are descriptive values, not independent confirmation or confidence
bounds.

| Comparator | Local Python 3.13 | GitHub Python 3.11 | GitHub Python 3.13 |
|---|---:|---:|---:|
| Noncontracting native control | 0.504428 | 0.449883 | 0.468682 |
| Persistent MiniCard | 0.489283 | 0.317596 | 0.325839 |
| Persistent CaDiCaL | 0.456792 | 0.309312 | 0.321636 |
| Reduced CUDD, natural order | 0.343641 | 0.227313 | 0.229789 |
| Reduced CUDD, incidence-BFS order | 0.415898 | 0.261574 | 0.267804 |
| Reduced CUDD, occurrence order | 0.399824 | 0.233529 | 0.231966 |
| Unreduced frontier CUDD, BFS | Incomplete | Incomplete | Incomplete |

Thus the new result survives a working generic compiler with ordinary logical
reduction, not merely three timed-out configurations. It does **not** show that
our native solver became faster in this checkpoint. Nor does it exhaust every
possible native BDD binding, preprocessing scheme or competing compiler family.

For a single request the SCC / noncontracting-control ratios are **0.994222**
locally, **1.007110** on GitHub Python 3.11 and **1.006279** on GitHub Python 3.13.
There is no consistent single-request advantage. Per-graph setup, mean and p95
measurements remain in the full audits. With only three repeated sessions, the
reported p95 is just the maximum order statistic, not a well-estimated tail.
Host noise and the notably different local/server ratios are retained rather
than pooled into a universal speedup.

### Negative and non-transfer evidence

The unfiltered synthetic development study retained **30 INCOMPLETE sessions out
of 210**, including **942 UNKNOWN responses** from the SPECTRA arms. The exact
comparators can decide infeasible requests that the existing API reports as
UNKNOWN. Those cells cannot earn complete-bank latency wins. That earlier
synthetic study did not include the final reduced-CUDD arms; their exact
seven-arm synthetic reproduction recipe is provided separately, not invented
as an executed benchmark.

WAP05/06 are real public conflict topologies, but the domains are synthetic and
the inherited bank was filtered for satisfiable requests. Prefixes overlap;
queries and repeats do not create additional graph clusters. No new holdout,
operator-defined trace, laptop or ARM result, outside-team replication, adoption,
or novelty review was obtained here. Project-owned GitHub runners are not
independent scientific replication. This leaner SCQ1 study cannot erase the
older frozen JSON endpoint's strict Python 3.11 failure.

against the cheapest exact alternatives, fresh transfer, outside replication and
useful adoption. More lines of code or passing internal tests alone do not close
those gates. The new compiler comparison does close a concrete weakness in the
previous evidence and makes the next challenge much more meaningful.
