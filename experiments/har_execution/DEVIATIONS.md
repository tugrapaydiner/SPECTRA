# Development and measurement history

The prospective remote protocol precedes data acquisition. The two fixed RBFs and
one LinearSVC were fitted before any test predictions. Two packing variants used
only the stored 128-row training probe; they failed the primary model's improvement
requirement. Their patches, source and measurements are preserved in the evidence.
Neither modifies the distributed runtime. The original existing-runtime evaluation
was fully locked and completed before linear-export development.

The linear-deployment extension is an explicit post-test response to the stronger
predeclared control. No model was refitted, no label was changed and no additional
classifier was selected. LINEAR_AMENDMENT.md and LINEAR_LOCK.json describe that
secondary scope. The specialized NumPy control beats the compiled path on warm
batches; the recorded outcome was not used to tune another native variant.

The first application attempt found that this container's sitecustomize imported
NumPy before native execution. Its single framework-control receipt and native
rejection are preserved. All accepted arms use Python -I -S; framework arms add the
same installed site-packages directory explicitly, without executing sitecustomize.
The NumPy-only control was also strengthened before the accepted matrix to read
inert coefficients directly rather than importing sklearn through a model pickle.
This prevents attributing sklearn's deployment cost to a plain NumPy calculation.

The accepted application matrix completed fourteen timing receipts before the tool
killed its parent near the last request. That last output was complete but its
parent timing receipt was unavailable. The output is retained as interrupted; only
that missing final timing was repeated. None of the other fourteen observations
was changed, retimed or omitted. All fifteen complete-output files and hashes were
then independently checked. Three process repetitions are descriptive observations,
not reliable tail-latency estimates or an independent deployment.

The first independent audit rejected a relative-path spelling in LINEAR_LOCK.json
that its path resolver did not handle. The resolver now supports the exact stored
relative and absolute forms; original hashes and files remain unchanged. Its final
complete audit passes. Generated-source tests, runtime and benchmark arithmetic
were not changed by that audit fix. The reproduction driver is a parameterized
version of the measured orchestration; exact original drivers and failure logs
remain in the evidence. No missing timing or result was reconstructed from guesses.
