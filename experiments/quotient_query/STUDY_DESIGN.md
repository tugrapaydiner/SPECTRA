# Prospective complete-session study — binding when FREEZE.json is committed

Candidate: fixed `scc` mode of the exact quotient compiler. The single contribution
under test is preservation of every original query address while compiling binary
implication equivalences once, then reconstructing and fully checking every complete
answer. This is classical compilation and execution, not learned reasoning or an
algorithmic-first claim.

Primary workload: repeated independent restrictions on synthetic heterogeneous
binary-choice wires with small multi-choice surroundings. Two construction families
(cyclic lists and random triangle trees), three fixed expansion lengths 64/192/576,
12 independently generated graphs per family/size, 12 wires per graph, 64 queries.
Each query restricts one randomly selected physical vertex per wire. Physical labels
are randomly permuted. Each core vertex has four colours and at most three binary
neighbours, with no core-core edges. Induction on the wire construction and the
four-minus-at-most-three argument prove every query admits a full solution. This
construction avoids interpreting fast UNKNOWN returns as complete-solve speed.

The queried address universe for the actual session prefix (1/8/64) is given to native SAT controls before their
preprocessing, allowing every other variable to be eliminated. Solvers receive no
wire boundaries or constructive phase assignments. All original graph arrays,
query records and full returned byte witnesses will be retained. The workload is
NOT a real compiler trace, measured deployment, broad-reasoning test or user adoption.

Primary budget is a complete 64-query session. One-query and eight-query sessions
are secondary cold-cost/amortization measurements and cannot replace a failed
primary gate. Candidate and every comparison must produce independently verified
complete SAT witnesses on every primary query in all three shuffled rounds.

Controls: direct original-domain reversible search with prepared core indexing;
cheap same-palette parity quotient; identical executor without compilation;
hybrid parity+SCC (ablation); bulk unmodified MiniCard; bulk unmodified CaDiCaL;
CaDiCaL with simplifying preprocessing; 16-valid-model-cache with retained CaDiCaL
fallback. SAT two-choice variables use one Boolean; wide variables need only
at-least-one, with no redundant at-most-one burden. Native solvers retain learning
through each session. All arms return full immutable byte witnesses and pay for
the same independently owned original-edge checker. Cache hits still pay its full
check. The compiler certificate verifier is a separate optional audit; its cost
will be reported, not silently described as part of ordinary measured setup.

Primary comparison uses the pointwise fastest CONVENTIONAL control's case/round-mean
session cost, choosing among domain, parity, MiniCard, CaDiCaL, simplifying CaDiCaL,
and cached CaDiCaL. This is an optimistic oracle for the baselines, not a deployable
router. Gate: the upper paired stratified case-bootstrap 95% bound on candidate /
oracle mean ratio <=0.50 and upper p95-session ratio <=1.10. Also require these
numerical conditions against every fixed conventional arm. Resample whole underlying
graphs within family/size strata, retaining all rounds; never treat queries or
rounds as independent graphs. Recompute oracle choice inside each bootstrap draw.
2000 fixed-seed draws. Secondary ablations and size/budget panels are descriptive.

Complete primary cost: decoded original task record -> tuple/input construction ->
query-address inventory and independent original checker -> fresh solver/compiler
setup -> every query restriction, solve, full answer creation and original check ->
release. File reading, JSON serialization, witness compression and IPC are outside
this in-memory API boundary, recorded separately. Imports and compilation are cold
costs outside primary timing; fresh-exec probes include import, case parsing and
one complete session. CPU work caps differ by backend and are guardrails, not equal
instructions. One pinned CPU, one numerical thread, 4-GiB process address-space
limit, 64-MiB candidate native construction/state payload caps; 2-second supervisor
session deadline after worker readiness, all timeouts charged observed elapsed
rather than removed/clamped. No hard real-time or universal RSS guarantee.

Preflight must check normal/sanitized implementations, actual installed package,
original source preservation, current complete source bindings, full pipeline,
all expected matrix roles, reconstruction and adversarial audit mutations. Publish
source hashes plus this complete protocol BEFORE generating the confirmation master
seed's task inventory. Fresh master seed has not yet been selected or generated.
Performance development is limited to the already exposed pilot cases and at most
one small SAT-generator development matrix. Preserve its raw rows and losses.
A failure after freeze is retained and invalidates clean confirmation; no tuning
or selected retries on that inventory. A second host repeats the exact fixed study,
not a new independent data sample or an outside researcher's replication.

## Pre-freeze audit completion

A clean confirmation additionally requires no worker execution errors and no failed
fresh-process resource probes. Deadline failures are retained, with primary failures
preventing acceptance. Development identity inventories are hash-bound by FREEZE.json,
not an editable list that can be shortened after observing overlap. The all-SAT
development inputs and small preflight are unchanged. No new performance-development
matrix is permitted in this continuation. Existing negative results remain negative.

Raw graph structure is the declared task equivalence: a differing unlabelled
colour-refinement signature rules out vertex-renaming isomorphism even after colour
renaming. This does not prove different algorithms or different quotient structures.
The deliberately redundant synthetic workload remains a narrow specialist test, not
evidence of broad transfer or novelty. Original lost predecessor records permit only
geometry-based exclusions where recorded vertex counts differ; unknown provenance is
not retrospectively certified by this study.
