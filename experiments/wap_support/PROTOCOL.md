# WAP repeated support-query study — prospective protocol

## Decision boundary

This study tests one narrow systems claim:

> For a fixed optical-network conflict topology with synthetic two-colour
> availability lists, exact SCC-equivalence compilation can reduce the complete
> cost of answering 1,024 distinct satisfiable support queries relative to a
> compact, persistent native MiniCard solver.

It does **not** test ordinary chromatic-number solving, deployed wavelength traces,
general SAT superiority, learned reasoning, algorithmic novelty, adoption, or an
asymptotic improvement. WAP graph topology is public application data; every list
and query is generated by the frozen code in `workload.py`.

## Data roles

Pinned upstream: `marijnheule/clicolcom` commit
`4932048642da2144f387961b595112277afff82f`.

Consumed development graphs: `wap01a.col`, `wap05a.col`, `wap06a.col`.

Prospective performance holdouts: `wap02a.col`, `wap03a.col`, `wap04a.col`,
`wap07a.col`, `wap08a.col`. Their byte lengths and Git blob identities are fixed
in `experiments/quotient_application/WAP_UPSTREAM_INVENTORY.json`. No holdout graph
may be replaced, filtered, regenerated, or omitted after opening.

All five holdouts are one public benchmark family and therefore only five
independent graph clusters. Query rows and timing orders are repeated observations,
not independent problems.

## Frozen workload construction

For each graph, deterministic DSATUR uses saturation, degree, then vertex ID as
its complete tie rule. Every three DSATUR colour classes are mapped to the binary
lists `{a,b}`, `{b,c}`, `{c,a}`. The fixed generator draws eight distinct original
vertices and one allowed colour at each vertex. Pinned MiniCard retains the first
1,024 unique satisfiable restrictions from at most 20,000 attempts. Using MiniCard
for admission is conservative for the primary MiniCard comparison.

The case record contains the full original edge set, lists, query bank, generator
seed, attempts summary, and a canonical SHA-256 identity. Construction time is
reported separately and is not part of the persistent service session. A claim
that includes building a new case must add construction cost explicitly.

## Arms

Primary candidate: `scc`, the exact original-address quotient using implication-SCC
equivalence substitution and complete witness lifting.

Primary external control: `minicard`, a persistent native MiniCard instance with
one Boolean per original lightpath and the exact compact binary-list encoding.
It retains learned clauses across all 1,024 queries.

Secondary arms: `hybrid`, `parity`, `none`, native `cadical195`, and a fixed
16-model cache in front of MiniCard. Secondary comparisons cannot replace failure
against MiniCard. The existing query order is tested forward, reverse, and with
one fixed shuffle.

## Complete cost boundary

Every measured session starts from the immutable case JSON and charges decoding
and digest validation, fresh index/formula construction, solver construction,
all 1,024 queries, complete immutable answer materialisation, an independently
owned original graph/list/query check for every answer, diagnostic collection,
and disposal. Native-module/PySAT import and process launch are reported by the
separate cold wall measurement. Case generation, graph download, source build,
evidence compression, JSON transport, and the optional independent compiler-
certificate audit are outside the primary persistent-session timer and disclosed
separately.

One process, one pinned CPU, one numerical thread, a 4-GiB address-space limit,
512-MiB admitted native payload limits, and a 60-second outer session deadline are
used. A timeout, crash, invalid answer, missing receipt, or resource refusal is a
failure; it is never dropped or converted into an imputed fast observation.

## Primary gate

All source, tests, graph identities, workload constants, arms, schedules, budgets,
analysis, and thresholds are committed before holdout acquisition. The holdout is
opened once.

The result passes only when all of the following hold:

1. Every scheduled session completes and all 107,520 holdout answers
   (`5 graphs × 7 arms × 3 orders × 1,024 queries`) have durable full witnesses.
2. Every candidate and MiniCard answer passes the original graph, list, and query
   checker; evidence and source manifests pass without repair.
3. The graph-clustered exact bootstrap upper 95% bound for the pooled complete-cost
   mean ratio `SCC / MiniCard` is at most **0.50**.
4. The corresponding upper 95% p95-cost ratio is at most **1.10**.
5. SCC's mean complete session cost is lower than MiniCard's on every holdout graph.

The exact bootstrap enumerates all `5^5 = 3,125` resamples of whole graphs while
retaining all three orders and both arms together. It does not resample queries or
timing orders as independent evidence. Statistics are descriptive for this fixed
benchmark family, not a production service-level guarantee.

## Integrity and stopping rule

The holdout workflow first verifies the frozen source inventory, runs the complete
public contracts and the focused native sanitizer suite, acquires exactly the five
pinned holdout blobs, constructs all cases, then executes the immutable schedule.
Raw graph bytes, generator attempts, full outputs, failures, environment, build
receipts, source archive, and manifests are retained.

Any post-opening change to candidate behaviour, competitor behaviour, workload,
threshold, case selection, budget, or primary analysis requires a new prospective
study with different unopened data. A failed gate remains a failed result. CI or a
second machine is automated cross-environment reproduction, not independent-team
scientific replication.
