# SPECTRA Claims Ledger

Milestone 01 purpose: separate what the repository currently **implements**, what its tests actually establish, what has a reproducible measurement artifact, and what remains a **hypothesis**.

This ledger is intentionally stricter than README prose. A passing unit test does not upgrade a broad scientific or performance claim beyond the domain actually exercised by the test.

## Status vocabulary

- **implemented** — a concrete code path exists, but Milestone 01 does not have sufficient validation to claim the behavior more broadly.
- **unit-tested** — an existing test exercised the stated behavior on its documented/tested domain and passed in the Milestone 01 baseline.
- **measured** — a current, inspectable measurement artifact is present and sufficient to ground the claim. Measurement methodology and host assumptions still apply.
- **hypothesis** — the README statement is broader than the evidence currently available, or its required checkpoint/raw measurement/ground truth is absent.

## What Milestone 01 can support

The baseline supports a narrower but useful set of statements:

1. The Python model/evaluation plumbing is healthy enough that the selected fast suite passes on the recorded environment.
2. The standalone native ternary kernel is correct on the **tested, aligned** AVX2 shapes.
3. The optional PyTorch extension builds with the current resolved PyTorch after the minimal C++20 compatibility update.
4. A tiny CPU training step has finite loss/gradients and changes model parameters.
5. VQ projection/idempotence and boundedness in the repository's constructed 30-step recurrence are unit-tested.
6. Latent-MCTS/verifier/halting **mechanics** have passing tests, subject to the grounding and postprocessing limitations above.

It does **not** yet support the broad performance, energy, trained-scaling, end-to-end reuse, arbitrary-depth VQ, compute-saving halting, or grounded self-improvement claims listed as hypotheses above.
