# SPECTRA Claims Ledger

Purpose: separate what the repository currently **implements**, what its tests actually establish, what has a reproducible measurement artifact, and what remains a **hypothesis**. Passing a unit test upgrades only the domain actually exercised by that test.

Detailed execution history and exact milestone evidence live in [`docs/RESEARCH_STATE.md`](RESEARCH_STATE.md).

## Status vocabulary

- **implemented** — a concrete code path exists, but current evidence is insufficient for a broader validation claim.
- **unit-tested** — tests exercise the stated behavior on the documented/tested domain and pass in the recorded milestone gate.
- **measured** — a retained/inspectable measurement artifact grounds the claim, subject to its host/methodology assumptions.
- **hypothesis** — the prose statement is broader than current evidence or its required trained checkpoint/raw measurement/ground truth is absent.

## Current evidence boundary

After M04, it is defensible to state that retained task/data contracts are explicit, Sudoku/maze semantic validation is strict on the tested domain, and bounded CPU training references have deterministic seed streams plus a versioned checkpoint/resume path that preserves model state, original schedule, sampler/data order, EMA identity, and—on the tested ternary path—the current quantization strength/schedule. The 8-step non-ternary audit reproduced uninterrupted raw/EMA state exactly, and the acceptance-specific ternary regression restored `rho=0.5` before continuation and matched the uninterrupted final state. It is also defensible to state that `fp16_amp` names an actual CUDA autocast/GradScaler path rather than an FP32 run with an FP16 label. It is **not** defensible to claim that the CUDA FP16 path was validated by M04, that GPU/distributed training is bitwise deterministic, that legacy weights-only files can exactly resume optimization, or that the tiny reference runs establish trained reasoning quality, scaling, energy, or hardware-performance results.
