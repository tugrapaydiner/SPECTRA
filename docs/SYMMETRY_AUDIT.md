# Sudoku4 symmetry audit: exact split disjointness is not structural disjointness

## Finding and its boundary

The consumed M14 development dataset is exact-disjoint but not disjoint under standard 4x4 Sudoku isomorphisms. This audit replays the original generator and verifies every example record against the pinned original manifest before computing any new result. It does not change the historical data, train a model, open a new confirmation set, or alter an acceptance threshold.

| Original split | Examples | Distinct input orbits | Rows with a training-equivalent puzzle |
|---|---:|---:|---:|
| Training | 4,096 | 2,410 | 4,096 |
| Validation | 512 | 477 | 331 (64.6484%) |
| Development, named `test` in the manifest | 512 | 481 | 351 (68.5547%) |

A training-only orbit lookup produces independently validated solutions on precisely those 351 development puzzles and abstains on all remaining 161. Keys depend only on puzzle inputs. Evaluation reference solutions are never supplied to lookup. A stored valid training answer is transported through an explicit invertible spatial/digit mapping; it is not retrieved by an evaluation label.

This is a limitation on claims of structural generalization, not proof of neural memorization. IID sampling from a finite distribution may legitimately contain equivalent problems. The original exact-disjoint in-distribution comparison is not erased. The overlap percentage above must not be attributed to the separate M14 confirmation set, which this audit does not inspect.

## The positive result does not disappear

Reaggregation of already-published development outcomes gives:

|---|---:|---:|---:|---:|

There are five model seeds, not 805 independent unseen puzzles. The candidate still leads by 11.4286 percentage points on the unseen-orbit stratum. This post-hoc stratification is descriptive: it is not a new confirmation, fresh neural inference, a causal test of memorization, or a matched-latency result for that stratum. Difficulty composition can differ across strata.

## Exact mathematical construction

Let G contain the Sudoku-preserving spatial maps generated by swapping the two bands, swapping rows within either band, the analogous column/stack operations, and transposition. For 4x4 boards it has 128 distinct maps. Digit relabeling contributes S4, of size 24. Blank zero remains fixed. Define

    C(x) = lexicographic minimum of normalize(g(x)), over g in G.

Here normalize assigns 1 to the first distinct nonzero symbol encountered, 2 to the next, and so forth. For each fixed spatial map, this is exactly the smallest representative over all digit permutations: the smallest available label must occupy each successive first occurrence. Missing digits are filled in deterministically to produce a complete invertible witness, but do not affect C(x).

Consequently C(x)=C(y) if and only if x and y lie in the same orbit of this declared group. A domain-separated SHA-256 digest is used as the operational key. Witness equality is also checked in the retrospective audit, so its reported matches are supported by actual transformations rather than hashes alone. This is standard finite-group canonicalization, not a claim of a novel symmetry algorithm or complete equivalence for arbitrary constraint problems. 9x9 boards are deliberately rejected.

## Implementation and verification

`data/sudoku_symmetry.py` contains input validation, canonical representatives, invertible witnesses and `Sudoku4OrbitLookup`. `data/splits.py` adds an opt-in group policy; `scripts/_common.py` threads it through the existing data-construction interface. Legacy defaults and manifests remain unchanged.

The 20 focused tests use an independent generator-closure construction of the spatial group rather than the production direct-product construction. They compare the canonical minimum with all 3,072 explicit spatial/digit transformations and check invariance for every transformed image. Additional tests cover missing symbols, witness round trips, lookup abstention and caller isolation, ancestral group exclusions, deterministic generation, augmentation, unsupported geometry and bounded rejection failures.

The initial immutable-source CPU run `34556191967`, commit `fbe4841c3ba0e1f1b385f696a92cca3fb1508dbd`, passed all 20 focused tests and exact audit replay on Python 3.11 and 3.13. These are focused tests, not a substitute for the full regression suite. The final pull request separately runs the repository CPU regression and frozen-inference checks. No GPU is used.

## Reproduce the historical audit

Use the repository's declared CPU environment and retained source archives, then run:

```bash
python -m pytest tests/test_sudoku_symmetry.py -ra
python scripts/audit_sudoku_symmetry.py \
  --out outputs/sudoku4-orbit-audit \
  --verify-report results/reliability/sudoku4_symmetry_audit.json
```

The output directory must not already exist. The report binds source-file hashes, the original manifest, source archive hashes, every replayed example inventory and all 5,120 witness records. It also verifies the retained development-row inventory before reaggregation. CI retains the complete tested source, package versions, JUnit, report and witnesses. Source changes affecting the report must be reviewed and the report explicitly regenerated; verification never silently blesses a replacement.

## Use orbit-aware splits for a NEW study

```python
from scripts._common import build_data_splits
from data.sudoku_symmetry import POLICY

splits, manifest = build_data_splits(
    cfg, n_train=48, n_val=12, n_test=12,
    grouping=POLICY,
    require_unique_groups=True,
    forbidden_fingerprints=ancestor_exact_and_orbit_keys,
)
```

This small example demonstrates the API, not a powered experiment. `cfg` must specify Sudoku with box=2. `ancestor_exact_and_orbit_keys` must be a frozen set containing the exact fingerprints AND canonical input orbit keys from every consumed ancestor dataset: core training, validation, verifier training, policy training and selection. Existing ancestry manifests created under the new policy carry orbit keys in `group_id`, so `ExclusionIndex` can close over them. Old exact-only manifests do not retroactively contain those keys: replay and canonicalize their inputs first.

`require_unique_groups=True` allows only one representative per group across the newly generated splits. Without it, equivalent examples may repeat inside one split but cannot cross split boundaries. Finite orbit counts and a bounded rejection budget can make a requested sample size infeasible; fail and redesign the preregistered dataset rather than lowering the disjointness requirement or repeatedly searching for a favorable seed. The historical recipes remain unchanged so frozen checkpoint replay is still meaningful.

A group-disjoint split changes the sampling distribution. Publish both the legacy IID reference and the new structural-transfer evaluation with separate claims; do not compare a newly retrained candidate to an old baseline on different data.
