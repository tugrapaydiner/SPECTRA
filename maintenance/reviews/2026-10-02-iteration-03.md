# Iteration 03: require a complete resource audit matrix

Reviewed base: `a5e0074b3cfb959ed54d7cbf86a4dc1eb93cc646`, the saved kit fix in
PR #48. This iteration changes the experimental recorded-data auditor, not a
model, numerical runtime, historical observation or production default.

## Reproduced false success

The resource auditor required 48 observation rows but then iterated
`zip(observed, resource['jobs'])`. It did not require a complete schedule. An empty
schedule skipped all process receipts and still returned
`isolated_resource_processes: 48` and `status: PASS`. A regression fixture also
records a failed process exit; the empty schedule hid that failure.

Short and excess schedules, duplicated jobs, unknown task/policy identities and
Boolean repeat IDs could also pass. Boolean `False` was accepted as process exit
code zero because Python considers the values equal. The initial regression set
reproduced **9 failures and 2 positive passes** on the reviewed base.

A subsequent check reproduced another omission: `compare(record, {})` checked
nothing, so a process receipt with empty JSON output passed. The final 15-case
set against the exact base auditor produced **13 failures and 2 positive passes**.
That comparison loaded the base module from Git in a separate test process;
neither the working source nor the historical evidence was replaced.

## Change and validation

The auditor now validates 48 jobs and 48 observations before pairing them. Jobs
must cover the complete four-task/four-policy Cartesian product with three
distinct nonnegative integer repeat IDs and no duplicates. It preserves recorded
ordering and does not impose a new zero-based or one-based repeat convention.
Each observation must match its job, and every corresponding process receipt must
have a genuine integer zero exit code and matching recorded output. Its parsed
output must contain the complete resource-probe fields, positive integer setup
time/model size/memory readings, valid byte identities and the recorded context.

The negative auditor adds empty, short and excess resource-schedule mutations,
plus an empty process output, to its existing twelve cases. The current README distinguishes these 16 cases from
the original twelve recorded in the historical RESULTS.md, which is unchanged.

Counts overlap: the 15 new tests are included in the 174-case suite. The fixture
has 756 fabricated timing *records* and four tiny replay records solely to reach
the full recorded-data audit path. Its source/model placeholders are inert. No
timing is measured, no native model is loaded, and no mathematical proof,
real-dataset replay, accuracy or performance conclusion comes from this fixture.

The original full retained evidence delivery is not present in this checkout, so
this iteration does not claim to have rerun its audit or its 48 real resource
processes. Hash checks and record consistency still do not authenticate clocks or
protect against a malicious rewrite of the complete evidence.
