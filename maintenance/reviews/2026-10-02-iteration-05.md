# Iteration 05: replay checks survive optimized Python

Reviewed base: `876d93e25b6196e9f48c2165b35c48d8411d3232` in PR #48.

The replay producer used Python `assert` for source-label, native-score and
prediction agreement. Running it with `python -O` removed those checks, including
native score calls inside the assertions, and allowed a final PASS report after
disagreement. A separate `all(... zip(predictions, expected))` check accepted a
matching prefix when predictions were shortened, even without optimization.

Ten isolated-process regression cases produced **5 failures and 5 passes** before
the fix. They use four tiny real source models and the actual total-tree runtime.
An explicitly substituted Python control stands in for the exported-C++ backend;
this checks orchestration failures and is not a CatBoost/backend comparison.
Fault injection covers wrong reference labels, changed retained scores, changed
stress scores and truncated predictions under both ordinary Python and `-O`.

Replay acceptance now uses explicit `ValueError` checks and requires the complete
prediction inventory. Correct replay still works in both interpreter modes.
Failure preserves diagnostic partial artifacts but does not write the final
`report.json` success record. Native arithmetic and original evidence are unchanged.

Observed on Linux x86-64, CPython 3.12.14, pytest 9.0.2:

| Check | Result |
| --- | --- |
| Focused cases before the fix | 5 failed, 5 passed |
| Focused cases after the fix | 10 passed, 3.80 s |
| Complete tree suite | 205 passed, 16.10 s |
| Historical workspace audit | 449 protected files and recovered helper byte-identical; 58 guide links valid |
| `git diff --check` | Passed |

The ten cases are included in the total. Their tiny fixtures and generated stress
rows are correctness controls, not new dataset accuracy or performance evidence.
This iteration does not claim a fresh replay of the original retained corpus.
